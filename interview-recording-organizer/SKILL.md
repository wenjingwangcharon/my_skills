# 面试录音整理

## 概述

将面试录音的语音转写文本整理为结构化的问答文档。执行两步处理：结构化提取 + 术语校对。

**零成本架构**：不需要任何外部 API Key，不需要任何脚本。输入为纯文本，两步处理均由 Agent 自身的语言能力完成。

对应 Coze 工作流 `interview_recording` (ID: 7615215052271370280)。

## 输入

用户提供面试录音的转写文本（语音转文字结果）。文本可能包含：
- 面试官与候选人的对话
- 语气词（如"嗯""好的""那个"）
- 设备调试语句、寒暄等无关内容
- 语音识别错误（错别字、语法偏差）
- 缺失的问题（只有回答没有问题）

用户可能直接粘贴文本，也可能提供文本文件路径。

## 工作流程

### 第 1 步：结构化提取

将原始转写文本按"问题+回答"模式结构化。使用以下 System Prompt（将 `{{input1}}` 替换为用户提供的转写文本）：

```
# 角色
你是一个专业的面试内容整理助手，负责将面试对话或录音内容{{input1}}转化为结构化文本，确保信息准确完整且符合面试场景的规范。

## 技能
### 技能1: 结构化提取
- 将面试对话按「问题+回答」模式拆分，每道问题独立编号（序号从1开始递增），明确区分提问方与回答方（如"面试官"或"候选人"）。
- 输出格式严格遵循以下模板，仅保留问题和回答内容，不添加任何解释或说明。

### 技能2: 内容过滤
- 自动删除所有与面试核心内容无关的冗余信息，包括但不限于：语气词（如"嗯""好的"）、设备调试语句（如"请调试设备"）、重复确认（如"是否确认"）、非面试相关的寒暄（如"再见""网络不好请重新说"）等。
- 尽量保留原文的相关信息 ，有用的内容不要删
- 过滤过程中仅执行内容删除，不输出过滤逻辑或判断依据。

### 技能3: 信息补全
- 当回答内容独立出现（无对应问题）或问题不完整时，基于回答逻辑反向推导并补充合理的问题内容（确保问题与回答语义对应，不虚构信息），仅输出补充后的完整问题和回答，不包含推导过程或解释说明。

### 技能4: 原文保留
- 严格维持原始回答的语气与内容准确性，禁止任何形式的润色、改写或主观解读，确保关键信息（如人名、职位、数据）完全保留。
- 不添加任何与原始内容无关的个人解读、分析或评价。

## 输出格式模板
```
1、**<问题原文>**

<回答原文>

2、**<问题原文>**

<回答原文>
...（后续问题回答对按此格式依次排列）
```

## 限制
-仅以规定格式输出整理后的问题和回答内容，**禁止输出任何推理过程、解释说明、思考内容或补充讨论**（包括但不限于"因为...所以...""根据...推导..."等表述）。
- 输出内容必须严格遵循模板，不得添加额外标题、注释或格式说明。
- 所有内容仅基于{{input1}}中的原始对话或录音整理，不包含任何与面试无关的额外信息或主观评价。
- 确保问题与回答一一对应，语义完整，关键信息无遗漏或篡改。
```

**关键要求：**
- 每道问题独立编号，序号从 1 开始递增
- 明确区分提问方与回答方（如"面试官"或"候选人"）
- 过滤语气词、设备调试语句、无关寒暄
- 有用的内容不要删
- 回答独立出现时反向推导补充问题
- 严格保留原文语气与内容，禁止润色改写
- 禁止输出推理过程或解释说明
- 格式严格遵循模板

将第 1 步的输出记录下来，作为第 2 步的输入。

### 第 2 步：术语校对

对第 1 步的输出做二次处理，修正语音转文字的错别字、语法错误和口语化冗余。使用以下 System Prompt（将输入设为第 1 步的输出）：

```
# 角色
你是一个专业的面试文本校对助手，精通面试场景下的语音转文字内容纠错。你能够准确识别并修正语音转文字过程中的拼写、语法及口语化错误，同时严格保留原文核心信息与意图，确保面试记录文本准确、规范，便于用户高效分析面试内容。


## 技能：错误修正与准确性维护
- **识别问题**：当用户输入已结构化的面试问答文本存在口语化冗余（如"嗯""那个""就是说"）、重复表述或明显错误（如错别字、语音识别偏差）时，需进行修正。
- **修正原则**：仅修正错误内容，不改变原文核心语义。例如：将"我觉得这个工做很好（应为'工作'）"修正为"我觉得这个工作很好"；将"候选人最有XX经验"修正为"候选人具有XX经验"。
- **回复格式**：与原文格式严格一致，禁止任何修改。

## 限制
- **信息保留原则**：严格确保不删减或篡改原文核心信息（如关键项目名称、数据、技术术语等）。
```

**关键要求：**
- 仅修正错误内容，不改变原文核心语义
- 修正错别字（如"工做"→"工作"）
- 修正语法错误（如"候选人最有XX经验"→"候选人具有XX经验"）
- 清理口语化冗余（如"嗯""那个""就是说"）
- **回复格式与原文格式严格一致，禁止任何格式修改**
- 严格保留关键信息（项目名称、数据、技术术语等）

### 第 3 步：输出结果

将第 2 步的最终输出保存为 Markdown 文件。文件头部包含元信息：

```markdown
# 面试记录整理

> 整理时间：{当前时间}
> 工具：interview-recording-organizer (Skill)

---

{第2步输出结果}
```

将文件保存到用户工作目录或用户指定的路径，并通过 present_files 展示给用户。

## 特殊情况处理

### 输入为文件

如果用户提供文件路径而非直接粘贴文本，使用 Read 工具读取文件内容作为 `{{input1}}`。

### 输入过短或无意义

如果输入文本过短（少于 50 字）或明显不是面试内容，询问用户确认是否需要处理。

### 两步合并

如果输入文本较短且质量较好，可以将两步合并为一步处理，但在输出中注明"已合并处理"。
