# 面试邮件整理

## 概述

从用户已连接的邮箱（QQ / 网易 / 163 等支持 IMAP 的邮箱）拉取邮件，筛选面试/招聘相关邮件，按内容自动分类并创建飞书日程或任务。

**架构**：
- 邮件读取：已连接的邮箱连接器（QQ邮箱 / 网易邮箱等，自动探测，优先）或 Python IMAP 脚本（后备，任意 IMAP 邮箱）
- LLM 处理（过滤/分类/提取）：Agent 自身语言能力，零 API 成本
- 飞书日历：`lark-calendar` skill
- 飞书任务：`lark-task` skill

对应 Coze 工作流 `email_interview` (ID: 7641193918574739491)。

## 前置条件

1. **邮箱**：已连接任意邮箱连接器（QQ邮箱 / 网易邮箱等，推荐），或准备好邮箱地址 + IMAP 授权码（后备方案）
2. **飞书**：已连接飞书连接器（用于创建日历事件和任务）。注意：连接器 connected ≠ lark-cli 已授权；实际创建走 lark-cli，需用户本人在飞书扫码完成 OAuth 用户授权（与连接器是两套独立授权）

## 安装与使用（给别人）

### 安装到本机

- **手动安装（最简单）**：把本 skill 文件夹（`email-interview-organizer/`，含 `SKILL.md` + `scripts/`）整体复制到目标机器的 `~/.workbuddy/skills/` 目录下，重启 WorkBuddy 即可生效。
- **市场安装**：若已发布到 WorkBuddy 推荐市场，可在市场搜索 `email-interview-organizer` 一键安装。

### 触发方式

- 对话中说「整理面试邮件」「看看最近的面试邮件」「帮我安排面试日程」「面试邮件处理」等，WorkBuddy 会自动匹配本 skill；
- 或显式调用：`@skill email-interview-organizer`。

### 使用前准备（两步，缺一不可）

**1. 邮箱来源（二选一）**

- 连连接器：左侧「连接器」面板连「QQ邮箱」或「网易邮箱」，skill 会自动探测用哪一个；
- 或不连连接器，直接提供 **邮箱地址 + IMAP 授权码**（网易邮箱设置里叫「客户端授权密码」，**不是登录密码**）。

**2. 飞书（两步，第二步最容易被坑）**

- 左侧「连接器」面板连「飞书」；
- **还要在飞书里扫码完成 lark-cli 的 OAuth 用户授权** —— 连接器显示 connected ≠ lark-cli 已授权，这是两套独立授权。不扫码的话，邮件能拉、能分类，但日历/任务推不到飞书。

### 运行流程

说一句话 → 拉邮件 → 筛招聘相关 → 按「日程/任务/信息」分类 → 推飞书日历/任务 → 出汇总报告。下游分类与推送逻辑与用哪个邮箱无关。

### 给安装者提个醒

- **不依赖 Coze**：灵感来自某 Coze 工作流，但实际由本地 Agent 跑（LLM 处理零 API 成本），不需要 Coze 账号；
- **后备 IMAP 脚本仅用 Python 标准库**（imaplib），对方无需 `pip install` 任何依赖；
- 想与 `job-application-tracker`（投递追踪）联动，需同时安装该 skill（见下方联动章节）。

## 工作流程

### 第 1 步：获取邮件

#### 方式 A：邮箱连接器（优先，自动探测）

自动探测当前已连接的邮箱连接器（如 QQ邮箱 `qq-mail`、网易邮箱 `netease-mail`）。调用其读取邮件的工具获取收件箱最新 30 封邮件。若同时存在多个可用连接器，优先使用用户指定的；未指定则使用第一个可用的。

#### 方式 B：Python IMAP 脚本（后备，任意 IMAP 邮箱）

如果无可用邮箱连接器，使用通用 IMAP 脚本获取邮件，支持任意 IMAP 邮箱（QQ、网易/163、Gmail 等）。需要向用户询问：
- 邮箱地址
- IMAP 授权码（非邮箱登录密码，在对应邮箱设置中生成，如网易邮箱为"客户端授权密码"）

运行脚本：

```bash
python <skill_dir>/scripts/fetch_emails.py --email <邮箱地址> --auth-code <授权码> --count 30 --output <输出JSON路径>
```

脚本输出 JSON 格式的邮件列表，每封邮件包含：`subject`（主题）、`from`（发件人）、`date`（日期）、`content`（正文）。

**依赖**：仅需 Python 标准库（imaplib），无需安装第三方包。

### 第 2 步：过滤和精简邮件

对获取的邮件列表执行过滤和精简。使用以下 Prompt（将 `{{input}}` 替换为邮件列表 JSON，`{{time}}` 替换为用户指定的时间阈值，未指定则用 30 天前）：

```
step1：判断{{input}}中的每封邮件是否和招聘相关，如果是，保留，如果不是，直接删掉。
判断邮件时间是否晚于{{time}}，如果晚，保留，如果早，直接删掉。
step2：将内容分条整理，列出每封邮件的时间、内容。
时间要具体到分钟。
内容尽量保持原文，如果原文语意不通，可以加上一些文字使内容连贯。
内容中如果有链接，必须保留。
step3：精简内容
如果这是一个测试邮件，保留描述和测试链接即可；
如果这是一个邀约面试的邮件，保留描述和选择面试时间的链接；
如果这是一封面试邮件，保留描述和面试链接；
如果这是一封offer邮件，保留描述offer链接。
step4：采用"每封邮件的内容作为一个独立值"的结构输出整理后的面试文本
```

**处理要求**：
- 只保留招聘相关邮件（面试邀约、测评通知、offer 等）
- 按时间过滤（只保留指定时间之后的邮件）
- 精简内容但保留关键链接
- 每封邮件作为独立条目输出

将输出记录为邮件条目列表，每个条目是一段精简后的邮件文本。

### 第 3 步：逐封分类和处理

对第 2 步输出的每封邮件，执行意图分类。

#### 3a. 意图分类

对每封邮件，使用以下 Prompt 分类（将 `{{query}}` 替换为邮件内容）：

```
分析{{query}}，
如果是面试邮件，告诉我什么时候面试，则为"日程"。
如果是邀请选择面试时间、邀请测评，则为"任务"。
如果是其他，则为"信息"。
```

分类结果：
- **日程** → 执行第 3b 步（创建飞书日历事件）
- **任务** → 执行第 3c 步（创建飞书任务）
- **信息** → 跳过，仅记录

#### 3b. 日程分支 — 创建飞书日历事件

**提取字段**，使用以下 Prompt（将 `{{input}}` 替换为邮件内容）：

```
提取{{input}}中的内容，输出为
summary：提取公司、部门、岗位名称，例如美团核心本地商业AI产品经理面试
start_time：开始时间，参考格式：2006-01-02 15:04:05
end_time：结束时间，参考格式：2006-01-02 15:04:05。如果没有表明，设置为开始时间后一小时
description：其他内容
```

**输出格式**：直接输出以下四个字段（每行一个，用冒号分隔）：

```
summary: <标题>
start_time: <开始时间>
end_time: <结束时间>
description: <描述>
```

**创建日历事件**：加载 `lark-calendar` skill，使用提取的字段创建飞书日历事件：
- `summary` → 日程标题
- `start_time` → 开始时间（格式：yyyy-MM-dd HH:mm:ss）
- `end_time` → 结束时间（格式：yyyy-MM-dd HH:mm:ss）
- `description` → 日程描述
- `need_notification` → true（发送通知）

#### 3c. 任务分支 — 创建飞书任务

**提取字段**，使用以下 Prompt（将 `{{input}}` 替换为邮件内容）：

```
提取{{input}}中的内容，输出为
summary：先判断是邀请测试还是邀请面试，前方分别标【测评邀请】【面试邀请】。然后提取公司、部门、岗位名称，例如美团、核心本地商业、AI产品经理。最后撰写标题：【面试邀请】美团-核心本地商业-AI产品经理
start_time：开始时间，参考格式：2006-01-02 15:04:05。没有可以不写
end_time：结束时间，参考格式：2006-01-02 15:04:05。有可能会出现"三天内""五个工作日内"等描述，请根据邮件内容中提到的时间为基准推算具体截止日期。注意"工作日"不包含周末（周六、周日）。如果无法确定具体日期，请保留原文描述，不要猜测。
description：其他内容
```

**输出格式**：直接输出以下四个字段（每行一个，用冒号分隔）：

```
summary: <标题>
start_time: <开始时间>
end_time: <截止时间>
description: <描述>
```

**时间推算规则**：
- "三天内" → 以邮件日期为基准 + 3 天
- "五个工作日内" → 以邮件日期为基准 + 5 个工作日（跳过周六周日）
- 无法确定具体日期时保留原文，不猜测

**创建飞书任务**：加载 `lark-task` skill，使用提取的字段创建飞书任务：
- `summary` → 任务标题
- `description` → 任务描述
- `start_time` → 开始时间
- `end_time` → 截止时间

### 第 4 步：汇总报告

处理完所有邮件后，向用户输出汇总报告：

```
## 面试邮件整理报告

> 整理时间：{当前时间}
> 邮件范围：最近 {count} 封
> 工具：email-interview-organizer (Skill)

### 处理结果

| # | 类型 | 标题 | 时间 | 状态 |
|---|------|------|------|------|
| 1 | 日程 | 美团面试 | 2024-07-20 14:00 | ✅ 已创建日历事件 |
| 2 | 任务 | 【测评邀请】腾讯笔试 | 2024-07-22 23:59 | ✅ 已创建任务 |
| 3 | 信息 | 感谢信 | — | ⏭ 已跳过 |

### 详情

（列出每个创建的日程/任务的详细信息）
```

## 特殊情况处理

### 无面试相关邮件

如果筛选后没有招聘相关邮件，告知用户"最近 {count} 封邮件中没有面试相关邮件"。

### 邮件时间不明确

如果邮件中没有明确的时间信息：
- 日程类：询问用户具体面试时间
- 任务类：保留原文描述，不猜测截止日期

### 飞书创建失败

如果创建日历事件或任务失败：
1. 记录失败原因
2. 继续处理下一封邮件
3. 在汇总报告中标注失败项
4. 建议用户检查飞书连接器状态

### 连接器未连接

如果邮箱连接器或飞书连接器未连接：
1. 告知用户需要连接的连接器（邮箱：QQ邮箱 / 网易邮箱等；飞书：飞书连接器）
2. 邮件读取可回退到通用 IMAP 脚本（需用户提供邮箱地址 + 授权码）
3. 飞书操作无法回退：连接器 connected 不等于 lark-cli 已授权，需用户完成 lark-cli 的 OAuth 用户授权（独立扫码，详见 lark-calendar / lark-task skill）

## 与 job-application-tracker 联动

本 Skill 可与 `job-application-tracker` skill（`~/.workbuddy/skills/job-application-tracker/`）联动。

当用户说"从邮件更新进度""同步面试邮件"时：
1. 先执行本 Skill 的第 1-2 步（获取邮件 → 过滤精简）
2. 将提取到的邮件信息（公司、部门、岗位、邮件类型）传递给 job-application-tracker
3. job-application-tracker 执行模糊匹配和状态更新（详见其 SKILL.md 的"操作五"和"邮件联动"章节）
4. 再回到本 Skill 执行第 3-4 步（创建飞书日程/任务 + 汇总报告）

**联动时的数据流**：邮件 → email-interview-organizer 提取 → job-application-tracker 匹配+更新 → email-interview-organizer 创建日程/任务 → 双方输出汇总报告
